Villes : nos grilles comparées à leur API

Les transporteurs branchés ou presque branchés, dont on récupère la liste des villes par API : Power Delivery, Colivraison et Meta Livraison. Pour chacun, on compare les villes de la grille qu'il nous a fournie (fichier Excel, PDF ou CSV, transcrit dans notre référentiel) avec la liste que renvoie son API.

Listes récupérées en direct le , en lecture seule : GET elog.ma/apiclient/listcities, GET colivraison24h.ma/cities.php, GET api.metalivraison.ma/…/partner/cities. Nos grilles viennent de la base locale. Les noms sont comparés sans tenir compte de la casse, des accents ni de la ponctuation.

Comment lire les catégories
  • Identique : même nom des deux côtés. Rien à faire.
  • Orthographe différente : la ville existe chez eux sous un autre nom. Nous l'avons rapprochée et elle part par API sous leur nom et identifiant. À faire confirmer par le transporteur.
  • Rattachée (Meta seulement) : la localité n'existe pas chez eux. Elle part sous l'identifiant de la ville de l'agence, avec son nom ajouté à l'adresse. Meta doit accepter ce fonctionnement.
  • Absente : aucune correspondance sûre. La remise de ces colis ne peut pas passer par l'API et se fait par l'Excel du bon.

EST Livraison Pas de liste de villes

Leur API n'a aucun endpoint qui renvoie les villes. On ne peut donc rien comparer. Sur les 64 villes de notre grille, seule OUJDA est prouvée : le dépôt de test du 23/09/2026 l'a acceptée sans créer de nouvelle ville. Les 63 autres sont inconnues tant qu'EST ne nous a pas envoyé sa liste. Attention : leur API crée une ville qu'elle ne connaît pas au lieu de refuser le colis, d'où la prudence.
